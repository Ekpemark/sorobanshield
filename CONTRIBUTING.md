# Contributing to SorobanShield

Contributions should make rules more accurate, explainable, and testable for Soroban developers.

1. Open an issue describing the Soroban pattern, expected behavior, and SDK context.
2. Keep each pull request focused on one rule or documentation improvement.
3. Include safe and vulnerable examples for any new detection rule.
4. Do not submit private contract source code or undisclosed vulnerability details in public issues.

Run `npm.cmd run lint` and `npm.cmd run build` before opening a pull request.
