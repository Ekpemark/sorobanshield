# Demo walkthrough and recording script

## Live-demo checklist

1. Start the app with `npm.cmd run dev` and open `http://localhost:3000`.
2. Show the default intentionally unsafe Soroban Rust example.
3. Run the scan and explain one authorization finding and one storage-lifecycle finding.
4. Download the Markdown report and show the rule id, source line, and remediation.
5. State: “SorobanShield is audit preparation, not a professional audit.”
6. Show the public repository, architecture, threat model, roadmap, and tests.

## 3–5 minute video outline

- 0:00–0:30 — Problem: Soroban developers need Rust- and Soroban-aware review prompts early.
- 0:30–1:30 — Product: scan the included sample and explain transparent evidence.
- 1:30–2:15 — Architecture and local-first privacy model.
- 2:15–3:00 — Soroban review registry design and why source analysis stays off-chain.
- 3:00–4:00 — 30-day milestones, public code, and community validation plan.
- 4:00–5:00 — Limitations, request for feedback, and invitation to test the beta.

## Screenshot guidance

Capture three screenshots after the app is running: the landing page, a completed scan with findings, and the downloaded report opened in a text editor. Add them to `docs/screenshots/` and reference only real captures in grant materials.
